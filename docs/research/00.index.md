# Jakarta Servlet 6.x 지원 연구

## 요약 결론

- Servlet 5.0 → 6.0 전환은 **순수한 deprecated 제거 릴리즈**다. 새 시그니처가 거의 추가되지 않은 대신, 어댑터가 위임하던 메서드들이 jakarta 6.0 측에서 다수 사라진다 (`HttpSession.getValue/putValue/getSessionContext` 등, `HttpServletResponse.setStatus(int,String)`, `encodeUrl`, `encodeRedirectUrl`).
- 6.0 → 6.1 은 증분 릴리즈로 어댑터 입장에서 파괴적이지 않으나, 새 시그니처(`sendRedirect` 오버로드, 상태 상수)를 노출하지 않으면 6.1 기반 컨테이너에서 일부 기능 손실이 발생한다.
- 추가로 **컴파일 타깃이 분기**된다 (5.0=Java 8, 6.0=Java 11, 6.1=Java 17).
- 권장 접근은 **Gradle source-set 분리 + 버전별 어댑터 모듈 산출(`-servlet5`, `-servlet6`, `-servlet6.1` classifier)** 이다. 자세한 비교는 [40.support-strategy.md](40.support-strategy.md) 참조.
