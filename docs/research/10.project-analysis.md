# 1. 현 프로젝트 구조 분석

## 1.1 목적

이 모듈은 **`javax.servlet` 4.0 기반 레거시 웹 애플리케이션** 코드를 **`jakarta.servlet` 5.0 기반 WAS (Tomcat 10.0 등)** 위에서 실행시키거나, 그 반대 방향으로 객체를 변환하기 위한 **양방향 어댑터**다.

- `ServletAdapter.adaptToJavax(jakartaXxx)` → `javax.servlet.*` 래퍼 반환
- `ServletAdapter.adaptToJakarta(javaxXxx)` → `jakarta.servlet.*` 래퍼 반환

## 1.2 빌드 구성 (`build.gradle`)

| 항목 | 값 |
|---|---|
| `sourceCompatibility` / `targetCompatibility` | **1.8** |
| `javax.servlet:javax.servlet-api` | **4.0.1** (compileOnly) |
| `jakarta.servlet:jakarta.servlet-api` | **5.0.0** (compileOnly) |
| 테스트 프레임워크 | JUnit 5.8 + Mockito 5.6 |

두 API가 **compileOnly 로만 선언**되어 있어, 런타임 컨테이너의 servlet API와 충돌하지 않는다. 단일 산출물 안에 양쪽 인터페이스를 모두 구현한 클래스가 들어 있으나, 실제 호출 시 사용되지 않는 쪽 클래스는 로드되지 않는다.

## 1.3 패키지 토폴로지

```
com.snoworca.ServletAdapter            ← 공개 진입점 (정적 팩토리)
adapter.jakarta.servlet.*              ← javax → jakarta 어댑터 (래퍼)
adapter.jakarta.servlet.http.*
adapter.javax.servlet.*                ← jakarta → javax 어댑터 (래퍼)
adapter.javax.servlet.http.*
adapter.servletElementConverter.*      ← 양방향 공용 컨버터
  - ServletReqResConverter
  - ServletConverter (Servlet/Registration/Filter 변환)
  - AsyncContextConverter
  - StreamConverter (Input/Output Stream)
  - DescriptorConverter (JspConfigDescriptor)
  - EnumsConverter (SessionTrackingMode, DispatcherType 등)
  - HttpComponentConverter
  - ReadListenerConverter, WriteListenerConverter
```

## 1.4 핵심 설계 패턴

### 1.4.1 단순 위임 래퍼 (Decorator)
대부분의 클래스(예: `adapter.jakarta.servlet.http.HttpServletRequest`)는 원본 객체를 `final` 필드로 보유하고 각 메서드를 1:1 위임한다.

```java
public class HttpServletRequest extends ServletRequest
        implements jakarta.servlet.http.HttpServletRequest {
   private final javax.servlet.http.HttpServletRequest httpRequest;
   ...
   @Override public String getContextPath() { return httpRequest.getContextPath(); }
}
```

### 1.4.2 타입 그래프 재귀 변환
반환 타입이 다른 네임스페이스의 타입이면 즉시 래퍼를 다시 생성한다. 예: `getSession()` → `new HttpSession(...)`, `getServletContext()` → `new ServletContext(...)`. 이로 인해 객체 그래프 전반이 자동 변환된다.

### 1.4.3 예외 변환
`javax.servlet.ServletException` ↔ `jakarta.servlet.ServletException`을 try/catch로 감싸 변환한다.

### 1.4.4 컬렉션 변환
`Cookie[]`, `Collection<Part>`, `Map<String, ServletRegistration>` 등은 새 컬렉션으로 복사하며 항목 단위로 래핑한다.

## 1.5 현재 시점에서 식별된 코드 특이사항

| 위치 | 내용 | 비고 |
|---|---|---|
| `adapter/jakarta/servlet/http/HttpServletRequest.java:185` | `isRequestedSessionIdFromUrl()` 위임 구현 보유 | Servlet 6.0에서 인터페이스에서 제거됨 |
| `adapter/jakarta/servlet/http/HttpSession.java:38, 46, 54, 62, 70` | `getSessionContext`, `getValue`, `getValueNames`, `putValue`, `removeValue` | Servlet 6.0 에서 모두 제거 |
| `adapter/jakarta/servlet/http/HttpSessionContext.java` | 6.0에서 인터페이스 자체 삭제 | 클래스 통째로 컴파일 실패 예정 |
| `adapter/jakarta/servlet/http/Cookie.java:11, 15, 63, 67` | `setComment/getComment/getVersion/setVersion` | 6.0에서 `@Deprecated(forRemoval=true)`, 아직 존재함 (당장 깨지지는 않음) |
| `adapter/jakarta/servlet/http/HttpServletResponse.java:85, 90, 134` | `encodeUrl`, `encodeRedirectUrl`, `setStatus(int, String)` | 6.0에서 모두 제거 |
| `adapter/jakarta/servlet/ServletContext.java:96` | `log(Exception, String)` | 6.0에서 제거 |
| `adapter/jakarta/servlet/ServletRequest.java:124` | `getRealPath(String)` | jakarta 측에는 이미 5.0에서도 제거된 상태이나 코드는 javax 호출만 함 → jakarta 인터페이스에 없으므로 `@Override` 컴파일 실패 가능. 실제 5.0 API에서 ServletRequest에 `getRealPath`가 있는지 재확인 필요. |

→ 상세 매핑은 [30.compatibility-impact.md](30.compatibility-impact.md) 참조.

## 1.6 빌드 산출물

- `build.gradle:6` → `version '0.0.1'`
- 단일 jar 만 산출 (classifier 없음).
- 사용자는 자기 프로젝트에 `javax.servlet-api:4.0.1`을 추가하고 본 모듈을 의존하는 형태로 사용한다 (README §"How to use").
