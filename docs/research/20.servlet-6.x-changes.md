# 2. Jakarta Servlet 6.0 / 6.1 변경점 정리

본 장은 어댑터에 영향을 미치는 변경에 한정해 정리한다. 일반 마이그레이션 가이드 전체가 아니라, **현재 코드가 위임하는 메서드** 위주.

## 2.1 플랫폼 요구사항

| Servlet 버전 | 명세 | 참조 컨테이너 | 최소 Java |
|---|---|---|---|
| 5.0 | Jakarta EE 9 | Tomcat 10.0 | Java SE 8 |
| 6.0 | Jakarta EE 10 | Tomcat 10.1 | **Java SE 11** |
| 6.1 | Jakarta EE 11 | Tomcat 11 | **Java SE 17** |

→ 어댑터의 현 `sourceCompatibility = 1.8`은 5.0 까지만 컴파일 가능. 6.x 지원 모듈은 빌드 타깃 분기가 필수.

## 2.2 Servlet 5.0 → 6.0 변경 (파괴적 변경 집중)

5 → 6 은 **Big-Bang 정리 릴리즈**다. 새 기능 추가는 거의 없고, 수십 년간 deprecated 상태였던 API가 일괄 제거됐다.

### 2.2.1 `jakarta.servlet.http.HttpServletRequest`

| 변경 | 메서드 | 대체 |
|---|---|---|
| **제거** | `boolean isRequestedSessionIdFromUrl()` | `isRequestedSessionIdFromURL()` (대문자 URL) |

### 2.2.2 `jakarta.servlet.http.HttpServletResponse`

| 변경 | 시그니처 | 대체 |
|---|---|---|
| **제거** | `String encodeUrl(String)` | `encodeURL(String)` |
| **제거** | `String encodeRedirectUrl(String)` | `encodeRedirectURL(String)` |
| **제거** | `void setStatus(int sc, String sm)` | `setStatus(int sc)` (HTTP/2에서 reason phrase 부재) |

### 2.2.3 `jakarta.servlet.http.HttpSession` — **레거시 일괄 제거**

다음이 인터페이스에서 모두 사라진다:

- `HttpSessionContext getSessionContext()`
- `Object getValue(String)`
- `String[] getValueNames()`
- `void putValue(String, Object)`
- `void removeValue(String)`

또한 동반 인터페이스 **`jakarta.servlet.http.HttpSessionContext` 자체 삭제**.

### 2.2.4 `jakarta.servlet.http.Cookie`

| 변경 | 대상 | 비고 |
|---|---|---|
| `@Deprecated(forRemoval=true)` | `getComment`, `setComment`, `getVersion`, `setVersion` | 아직 존재. 향후 제거 예정. RFC 2965 → 6265 단일화 사유 |
| **신규** | `setAttribute(String, String)` | SameSite, Partitioned 등 임의 속성 |
| **신규** | `getAttribute(String)` |  |
| **신규** | `Map<String, String> getAttributes()` | unmodifiable |

→ Cookie attribute API는 javax 4.0 측에 부재하므로 jakarta → javax 매핑 시 **정보 손실 불가피**.

### 2.2.5 `jakarta.servlet.ServletContext`

| 변경 | 시그니처 | 대체 |
|---|---|---|
| **제거** | `log(Exception exception, String msg)` | `log(String msg, Throwable t)` (인자 순서·타입 정리) |

`getServlet/getServlets/getServletNames` 는 deprecated 유지(제거 아님). `getRealPath(String)`는 존속.

### 2.2.6 `jakarta.servlet.ServletRequest`

`String getRealPath(String)` 는 ServletRequest 측에서 5.0 이전에 이미 제거됨 (이미 현재 코드의 `adapter.jakarta.servlet.ServletRequest`에는 없음 — `adapter.javax.servlet.ServletRequest` 가 위임 시 jakarta 측에 호출하지 않는 구조). 6.0에서 추가 변경 없음.

### 2.2.7 클래스 단위 삭제

| 삭제 대상 | 비고 |
|---|---|
| `jakarta.servlet.SingleThreadModel` | 인터페이스 자체 삭제 |
| `jakarta.servlet.http.HttpUtils` | 클래스 자체 삭제 (Servlet 2.3부터 deprecated) |
| `jakarta.servlet.http.HttpSessionContext` | 위 2.2.3 참조 |

### 2.2.8 추가된 메서드 (5.0 → 6.0)

- `AsyncContext.hasOriginalRequestAndResponse()`
- `ServletRequest.getRequestId()`, `getProtocolRequestId()`, `getServletConnection()`
- `Cookie` attribute API (위 2.2.4)
- `HttpServlet.LEGACY_DO_HEAD` 필드 (`forRemoval=true`로 곧 사라질 예정의 호환 플래그)

## 2.3 Servlet 6.0 → 6.1 변경 (증분 릴리즈)

파괴적 변경 없음. 어댑터에서 6.0 코드를 6.1로 그대로 사용해도 컴파일 통과. 단, 새 시그니처를 노출하지 않으면 6.1 신기능을 어댑터 사용자에게 전달할 수 없다.

### 2.3.1 `HttpServletResponse` 새 시그니처

```java
void sendRedirect(String location, int sc);                       // 신규
void sendRedirect(String location, boolean clearBuffer);          // 신규
void sendRedirect(String location, int sc, boolean clearBuffer);  // 신규
```

### 2.3.2 새 상태 상수

| 상수 | 값 |
|---|---|
| `SC_PERMANENT_REDIRECT` | 308 |
| `SC_MISDIRECTED_REQUEST` | 421 |
| `SC_UNPROCESSABLE_CONTENT` | 422 |
| `SC_UPGRADE_REQUIRED` | 426 |

### 2.3.3 `HttpServlet`

`boolean isSensitiveHeader(String headerName)` 추가. TRACE 응답에서 민감 헤더 마스킹.

### 2.3.4 신규 deprecation

- `PushBuilder` 인터페이스 및 `HttpServletRequest.newPushBuilder()` 전체가 deprecated (HTTP/2 Push 폐기, HTTP 103 Early Hints 권장).
- `Cookie` / `SessionCookieConfig` 의 Comment/Version 계열은 `forRemoval=true` 유지.

### 2.3.5 보안

명세에서 Java SecurityManager 관련 표현 제거 (Java 17의 `@Deprecated(forRemoval=true)` SecurityManager 반영).

## 2.4 어댑터 관점 영향 요약

5.0 → 6.0 변경 중 어댑터에 실제로 영향이 있는 항목:

1. `HttpSessionContext` 클래스 부재 → `adapter.jakarta.servlet.http.HttpSessionContext` 클래스 자체 컴파일 불가
2. `HttpSession` 의 5개 레거시 메서드가 인터페이스에 없음 → `@Override` 컴파일 실패
3. `HttpServletResponse.encodeUrl/encodeRedirectUrl/setStatus(int,String)` 메서드 부재 → `@Override` 실패
4. `HttpServletRequest.isRequestedSessionIdFromUrl` 부재 → `@Override` 실패
5. `ServletContext.log(Exception, String)` 부재 → `@Override` 실패

→ 단순히 `@Override` 어노테이션 제거로는 해결되지 않는다. 인터페이스에 없는 메서드를 클래스가 갖고 있어도 컴파일 자체는 가능하나, 호출자가 javax 인터페이스를 통해 호출하지 못한다 (`javax.servlet.http.HttpSession.getValue` 는 javax 측에는 존재함). 즉 **javax → jakarta 방향(adapter.jakarta.*)에서 더 이상 위임할 jakarta 메서드가 없다**. 호출 시 동작을 정의해야 한다 (예: `UnsupportedOperationException`, 또는 attribute API 기반 fallback).
