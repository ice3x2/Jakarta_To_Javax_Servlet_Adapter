## §4 테스트 작성 컨벤션

기존 18 단위 테스트 클래스에서 추출한 컨벤션 — backfill 시 일관성 유지를 위한 SSOT.

### 4.1 fixture 패턴

- **mock 대상**: 외부 servlet API 인터페이스 (`javax.servlet.*`, `jakarta.servlet.*`) 만 mock. **어댑터 SUT 자체는 절대 mock 하지 않는다** (다중 파일에 명시: PartDefectTest.java doc:`§0.6 compliance: only the external servlet API interface is mocked. The SUT adapter classes are never mocked.`)
- **fake 객체**: Mockito 가 부적합한 (예: ServletContext init-param 검증) 경우 `adapter.common.testfakes.AbstractFakeServletContext` (servlet5/src/main/java/adapter/common/testfakes/) 의 fake base 를 사용한다. StrictModeTest.java:3 import 참조.
- **인스턴스 생성**: 어댑터 ctor 에 mock origin 을 직접 주입. 예: `new adapter.javax.servlet5.http.Cookie(origin)` (AdapterUnwrapAllClassesTest.java:191).

### 4.2 mock 정책 — FR-TEST-001 AC-3 잠금

- **smart-null answer**: SRS AC-3 (40.testing.srs.md:75) 는 `withSettings().defaultAnswer(RETURNS_SMART_NULLS)` 를 요구. 그러나 기존 18 단위 테스트 중 **명시적으로 RETURNS_SMART_NULLS 를 적용한 사례는 없음** — 모두 default `mock(Class)` 사용. backfill 시 **AC-3 준수를 위해 RETURNS_SMART_NULLS 명시 권장** (SRS 게이트 정합).
- **verify 순서 컨벤션**: 위임 검증은 `verify(origin).method(args)` 를 `assertEquals(...)` **이전**에 배치 (PartDefectTest.java doc:43-53, ServletResponseDefectTest.java doc:48-60, GetCookiesNullDefectTest.java doc:46-48). 이유 — Mockito 의 `WantedButNotInvoked` 가 위임 누락의 가장 직접적 신호이고, return-value `assertEquals` 가 mock-default 0/null 로 인해 misleading 실패를 만들 수 있음.
- **negative verify**: 잘못된 메서드 호출 차단은 `verify(origin, never()).wrongMethod(...)` 로 명시. positive verify 다음에 배치 (ServletContextEncodingDefectTest doc:52-64).

### 4.3 assertion 스타일

- **JUnit 5 (`org.junit.jupiter.api`)** + **Mockito 5.x** + **`@DisplayName`** 한국어/영문 혼용 권장 (CookieAttributePolicyTest.java:206-209 패턴).
- **failure message** 는 "expected: ..., got: ..." 포맷 + sidecar 의 `expected_failure_signature` 와 일치시킨다 (StreamConverterDefectTest.java:26-34, CookieAttributePolicyTest.java:81-83). backfill 의 green-phase 테스트도 동일 포맷 유지.
- **package 배치**:
  - SUT package 와 동일 (`adapter.jakarta.servlet5.http`) 에 두면 package-private ctor 직접 호출 가능 (PartDefectTest.java:55-57). HttpSession.java:12 의 default ctor 는 package-private 이므로 같은 패키지 배치 필요.
  - SUT 가 public 이면 `com/snoworca/` 패키지 배치 가능 (CookieAttributePolicyTest 처럼).
- **reflection vs direct**: Helper 클래스 부재 시점의 RED-phase 패턴은 `Class.forName(FQN)` reflection 사용 (StrictModeTest.java:60-78). green-phase backfill 은 direct call 권장.

### 4.4 메서드 이름 컨벤션

- camelCase + AC-ID 접미사: `shouldXxxxxFor_FRCONVNNN_ACN()` (CookieAttributePolicyTest.java:207, AdapterUnwrapAllClassesTest.java:146).
- backfill 의 green-phase 테스트는 sidecar `test_symbol` 매핑이 강제되지 않으므로, `should{Behavior}_{ClassName}_{MethodName}()` 또는 `test{ClassName}_{MethodName}_{Scenario}()` 형식 자유 (`ServletContextAdapterTest.java:11` 의 `testConvertServletContext()` 단순형 사용 사례).

### 4.5 `@req` annotation

기존 RED-phase 테스트는 javadoc 에 `@req FR-XXX-NNN` 태그를 명시한다 (CookieAttributePolicyTest.java:69, AdapterUnwrapAllClassesTest.java:59-60). backfill 의 9 신규 클래스는 모두 `@req FR-TEST-001` (필요 시 secondary 로 FR-CONV-NNN) 을 javadoc 에 포함하여 trace 유지.
