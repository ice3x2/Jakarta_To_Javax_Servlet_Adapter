## §3. servlet6 vs servlet61 차이 표면 (추가 API)

본 절은 servlet61 unit test 가 servlet6 unit test 대비 추가로 검증해야 할 API 의 전수 집합이다.

### §3.1 jakarta 6.0 → 6.1 신규 추상 메서드 (구현 의무 = override 존재)

| API | 위치 | 어댑터 구현 정책 | 검증 방법 (PH-005 단위 테스트 적합) |
|---|---|---|---|
| `HttpServletResponse.sendRedirect(String, int, boolean)` | jakarta 6.1 신규 | servlet61 only: `setStatus(sc)` + `setHeader("Location", loc)` + `clearBuffer=true` 시 `resetBuffer()` 선행, `flushBuffer()` 후속. SRS §6.2.2 policy E. | (1) `getDeclaredMethod` reflection 으로 declared concrete 여부 확인, (2) tracing fake response 로 `sendRedirect(loc, 303, true)` 호출 시 `setStatus(303)` + `Location=loc` + `resetBuffer()` + `flushBuffer()` 정확히 1회씩 호출 확인, (3) 원본 `sendRedirect(loc)` 위임 금지 확인. **이미 `SendRedirect61Test` (servlet61 only, 5 cases) 가 cover** — PH-005-04 는 본 시그니처를 재중복하지 말고 분기 (request charset / cookie / session) 14건에 집중. |

### §3.2 jakarta 6.1 이미 6.0 부터 존재하는 API (재검증 불필요, 6.0 base 정합성만)

다음 API 는 jakarta 6.0 부터 존재하며 servlet61 어댑터에서 6.0 코드 경로를 그대로 상속한다. PH-005-04 jakarta-side 14건의 일부로 `getRequestId/getProtocolRequestId/getServletConnection` 미러 검증 가능 (servlet6 의 `RequestIdTest` 2건과 동일 패턴).
- `ServletRequest.getRequestId()` — UUID lazy
- `ServletRequest.getProtocolRequestId()` — empty string
- `ServletRequest.getServletConnection()` — DummyServletConnection synth

### §3.3 servlet61 가 명시적으로 **추가하지 않은** 6.1 신규 표면 (의도된 deferral)

- **`Cookie` SameSite 정식 지원**: D3 결정으로 lossy 유지 (`Cookie.setAttribute/getAttribute/getAttributes` no-op + WARN once). servlet61 도 servlet6 와 동등하게 lossy 동작. PH-005-04/05 에서 SameSite 별도 검증 케이스 작성 시 servlet6/61 동일 결과 확인 (regression lock-in).
- **`ServletContext.setRequestCharacterEncoding(Charset)` Charset 오버로드**: jakarta 6.1 신규. 본 리포트 작성 시점 (`grep -n "setRequestCharacterEncoding.*Charset" servlet61/src/main/java/adapter/jakarta/servlet61/ServletContext.java`) 0 hits → 어댑터 본문 추가 미발견. **본 차이는 PH-005 범위 외 (구현 자체가 PH-004 책임이며 미구현 상태)** — 단위 테스트에서 다루지 말 것.
- **`HttpServletResponse.setTrailerFields(Supplier<Map<String,String>>)` 류 trailers API**: jakarta 6.0 부터 존재 (servlet6 도 동일). 별도 6.1 신규 표면 아님.

### §3.4 결론

servlet61 단위 테스트가 servlet6 대비 **반드시 추가로 검증해야 할 표면** 은 §3.1 의 `sendRedirect(String, int, boolean)` 단 1건이다. `SendRedirect61Test` (5 cases) 가 이미 cover. 따라서 PH-005-04 (jakarta 14건) 는 servlet6 의 PH-005-01 와 거의 동일한 분배를 따르고, 14 슬롯 중 1~2 슬롯 만 6.1 sendRedirect 회귀 lock-in (이미 cover 된 영역) 또는 추가 시나리오 (HEAD method / clearBuffer=false 동작 / sendRedirect(loc, 0, false) edge case) 로 사용한다.

### §6.2 fixture 재사용 가능성

#### §6.2.1 `adapter.common.testfakes` (servlet5 내부)

- `AbstractFakeHttpSession.java`
