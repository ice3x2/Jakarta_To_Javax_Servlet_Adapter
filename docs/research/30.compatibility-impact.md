# 3. 현 어댑터 ↔ Servlet 6.x 호환성 영향 매핑

## 3.1 컴파일 파괴 지점 (Build-Breaking)

본 절은 현 코드를 그대로 `jakarta.servlet-api:6.0.0` 으로 교체했을 때 컴파일 실패가 발생하는 지점을 모두 나열한다.

### 3.1.1 `adapter.jakarta.servlet.http.HttpServletRequest`

| 라인 | 코드 | 실패 사유 |
|---|---|---|
| L185-188 | `@Override public boolean isRequestedSessionIdFromUrl() { return this.httpRequest.isRequestedSessionIdFromUrl(); }` | `jakarta.servlet.http.HttpServletRequest` 인터페이스에 메서드 부재 → `@Override` 컴파일 실패. 또한 `javax.servlet.http.HttpServletRequest#isRequestedSessionIdFromUrl` 은 deprecated 이지만 javax 4.0 측에는 존속하므로 호출 자체는 가능 |

### 3.1.2 `adapter.jakarta.servlet.http.HttpServletResponse`

| 라인 | 메서드 | 실패 사유 |
|---|---|---|
| L85-87 | `encodeUrl(String)` | jakarta 6.0 인터페이스에서 제거 → `@Override` 실패 |
| L89-92 | `encodeRedirectUrl(String)` | 동일 |
| L134-137 | `setStatus(int sc, String sm)` | 동일 |

### 3.1.3 `adapter.jakarta.servlet.http.HttpSession`

| 라인 | 메서드 | 실패 사유 |
|---|---|---|
| L38-40 | `getSessionContext()` | jakarta 6.0 인터페이스 메서드 제거. 더 심각: 반환 타입 `HttpSessionContext` **클래스 자체가 jakarta 6.0에 없음** |
| L46-48 | `getValue(String)` | 인터페이스에서 제거 |
| L54-56 | `getValueNames()` | 인터페이스에서 제거 |
| L62-64 | `putValue(String, Object)` | 인터페이스에서 제거 |
| L70-72 | `removeValue(String)` | 인터페이스에서 제거 |

### 3.1.4 `adapter.jakarta.servlet.http.HttpSessionContext`

파일 전체가 6.0에서 컴파일 불가. `import jakarta.servlet.http.HttpSessionContext` 가 unresolved.

### 3.1.5 `adapter.jakarta.servlet.ServletContext`

| 라인 | 메서드 | 실패 사유 |
|---|---|---|
| L96-98 | `log(Exception, String)` | jakarta 6.0에서 시그니처 제거 |

### 3.1.6 `com.snoworca.ServletAdapter`

직접 깨지는 메서드는 없으나, 위 클래스들이 컴파일 불가이므로 모듈 전체가 산출되지 않는다.

### 3.1.7 영향 받지 않는 부분

- `adapter.javax.servlet.*` 측: javax 4.0 API 는 계속 사용되므로 deprecated 메서드도 그대로 호출 가능. 위임 대상이 jakarta 측인 메서드만 신경 쓰면 된다.
- `Cookie.getComment/setComment/getVersion/setVersion`: 6.0 에서 `forRemoval=true` 상태지만 **아직 인터페이스에 존재**. 즉시 깨지지 않음. 컴파일 경고만 발생.

## 3.2 의미론적 손실 지점 (Semantic Loss)

컴파일은 통과하지만 동작이 달라지는 지점.

### 3.2.1 Cookie attribute API 양방향 변환

jakarta 6.0 → javax 4.0 방향에서 손실:
- 사용자가 jakarta 측에 `cookie.setAttribute("SameSite", "Lax")` 를 호출했더라도, `adapter.javax.servlet.http.Cookie` 가 javax 4.0 Cookie 를 래핑할 때 attribute Map 자체를 표현할 필드가 없다.
- 대응: **(a)** 어댑터에 자체 attribute Map 을 보관하고 `addCookie` 시 응답 헤더에 직접 직렬화, **(b)** `Set-Cookie` 응답을 가로채 `; SameSite=...` suffix 를 붙이는 후처리, **(c)** 손실 허용하고 문서화. 현실적으로 (c) 가 가장 합리적이며, attribute API 가 필요한 신규 코드는 jakarta-native 로 이전하라고 안내.

### 3.2.2 ServletRequest connection 정보

`ServletRequest.getRequestId() / getProtocolRequestId() / getServletConnection()` 은 Servlet 6.0 신규. javax 4.0 측에는 대응 메서드가 없다. jakarta → javax 변환 시 어댑터가 호출되지 않으므로 무영향. javax → jakarta 방향(`adapter.jakarta.servlet.ServletRequest`)에서는 6.0 인터페이스에 새 메서드가 추가되므로 **반드시 구현해야 한다** (그렇지 않으면 abstract 클래스가 되어 컴파일 실패). 합리적 stub:
- `getRequestId()` → `UUID.randomUUID().toString()`
- `getProtocolRequestId()` → `""`
- `getServletConnection()` → 동기적으로 만들어진 `ServletConnection` 구현체 반환 (`getConnectionId`, `getProtocol`, `getProtocolConnectionId`, `isSecure`)

### 3.2.3 `sendRedirect` 오버로드 (6.1)

`adapter.jakarta.servlet.http.HttpServletResponse` 가 jakarta 6.1 인터페이스를 implements 할 때, 새 디폴트 메서드들이 인터페이스에서 default 구현으로 제공된다(명세상 default 표시 — 6.1 javadoc 확인 필요). default 메서드면 컴파일은 통과하나, javax 4.0 측에 대응 시그니처가 없어 위임 시 동작이 단순 `setStatus + setHeader("Location", ...)` 로 폴백된다.

## 3.3 런타임 동작 영향

| 상황 | 5.0 어댑터를 6.0 컨테이너에서 그대로 실행 (재컴파일 없이) | 
|---|---|
| 컨테이너 클래스 로더가 5.0 시그니처 메서드를 인터페이스에서 못 찾음 | jakarta 6.0 인터페이스에서 사라진 메서드(예: `getSessionContext`)를 어댑터 클래스가 가지고 있어도, **인터페이스 메서드 테이블에는 없으므로 호출 불가** |
| jakarta 6.0 인터페이스에 새로 추가된 추상 메서드 (`getRequestId` 등) | 어댑터 클래스가 이를 구현하지 않으면 `AbstractMethodError` 가 호출 시점에 throw 됨 |

→ **결론: 재컴파일 없이 동작시키는 길은 없다.** 어댑터를 6.x 대상으로 새로 빌드해야 한다.

## 3.4 변경 작업 추정량

| 카테고리 | 수정 단위 | 추정 |
|---|---|---|
| 메서드 삭제 (@Override 제거) | `HttpServletRequest`, `HttpServletResponse`, `HttpSession`, `ServletContext` | 약 10건 |
| 파일 통째 삭제 | `HttpSessionContext.java` (jakarta 측) | 1파일 |
| 새 메서드 stub 구현 | `ServletRequest.getRequestId/getProtocolRequestId/getServletConnection` | 3건 + `ServletConnection` 구현체 1개 |
| Cookie attribute API 위임 추가 (선택) | `setAttribute/getAttribute/getAttributes` | 3건 |
| `sendRedirect` 오버로드 (6.1 only, default 메서드 활용 가능) | 0~3건 |
| `HttpServlet.isSensitiveHeader` | 0~1건 |

총 **약 15~20개 메서드 + 1 신규 보조 클래스** 분량. 새 클래스 트리 전체를 새로 작성할 필요는 없다.
