## 1. Scope Overview

본 문서는 `Jakarta_To_Javax_Servlet_Adapter` 1.0 의 Gradle 빌드 토폴로지·패키지 구조·의존 그래프·진입점 클래스 배치를 정의한다. 5.0 / 6.0 / 6.1 jakarta servlet 버전을 동시에 지원하기 위한 multi-module 분리가 핵심이다.

배경과 결정 근거는 [docs/research/50.architecture.md](../research/50.architecture.md) 및 [docs/research/55.module-split-decision.md](../research/55.module-split-decision.md) 를 참조한다.

## 2. Scope Boundaries

### In Scope

- Gradle 멀티 모듈 토폴로지 정의 (`settings.gradle`, root `build.gradle`, 모듈별 `build.gradle`)
- 모듈별 jakarta-servlet-api 의존 버전 핀
- 모듈별 Java 컴파일 타깃
- `common` 모듈에 둘 수 있는 코드의 ABI 호환성 규약
- 자바 패키지 네이밍 규칙 (`adapter.jakarta.servletN.*`, `adapter.javax.servletN.*`, `adapter.common.*`, `adapter.servletElementConverterN.*`)
- 사용자 진입점 (`com.snoworca.ServletAdapter` + `ServletAdapterN` 별칭)
- BOM 모듈

### Out of Scope

- 변환 의미론과 폴백 정책 (→ `CONV`)
- 0.0.1 레거시 결함 수정 (→ `FIX`)
- 테스트 토폴로지 (→ `TEST`)
- Maven Central 게시·마이그레이션 가이드 (→ `REL`)
- JPMS `module-info.java` 본격 도입 (v1.1.0 이후 검토)

## 3. Assumptions and Constraints

- `javax.servlet:javax.servlet-api` 의존은 **4.0.1 로 고정**한다. 다른 javax 버전 지원은 v1.0.0 범위 밖이다.
- `jakarta.servlet:jakarta.servlet-api` 의존 버전은 모듈별로 다르다 (5.0.0 / 6.0.0 / 6.1.0).
- Gradle Toolchain 으로 JDK 8 / 11 / 17 을 자동 다운로드한다.
- 본 프로젝트의 group ID 는 `com.clipsoft` 를 유지한다.
- `common` 모듈은 5/6/6.1 ABI 가 모두 동일한 심볼만 참조한다. ABI 호환성이 깨지는 신 버전 등장 시 본 가정은 재평가된다.

| 모듈 디렉토리 | 책임 |

#### Rationale

#### Acceptance Criteria

- [ ] `settings.gradle` 에 `include 'common', 'servlet5', 'servlet6', 'servlet61', 'bom'` 가 존재한다.
- [ ] 각 모듈 디렉토리에 `build.gradle` 파일이 존재한다.
- [ ] `./gradlew projects` 가 5개 서브 프로젝트를 모두 나열한다.
- [ ] `./gradlew buildAll` (또는 `./gradlew build`) 가 5개 모듈 전체를 성공적으로 빌드한다.

### FR-MOD-004 — common 모듈은 ABI 호환 컨버터만 포함

| Field | Value |
|---|---|
| Type | functional |
| Target | v1.0.0 |
| Status | planned |

| Priority | high |
| Tags | common, abi, converter |
| Related Docs | [50.architecture.md §2.1~2.2](../research/50.architecture.md) |

#### Requirement

`common` 모듈에 둘 수 있는 코드는 jakarta 5.0 / 6.0 / 6.1 ABI 가 모두 동일한 심볼만 참조한다. 1.0 시점에서 common 에 포함되는 클래스는 다음으로 한정된다.

| 클래스 | 책임 |
|---|---|
| `adapter.common.EnumsConverter` | `SessionTrackingMode` enum 매핑 |
| `adapter.common.HttpComponentConverter` | `DispatcherType` enum 매핑 |
| `adapter.common.ReadListenerConverter` | `ReadListener` 양방향 변환 |
| `adapter.common.WriteListenerConverter` | `WriteListener` 양방향 변환 |
| `adapter.common.ConverterSupport` | 공용 예외 변환 헬퍼 등 |

다른 컨버터 (`ServletReqResConverter`, `ServletConverter`, `StreamConverter`, `DescriptorConverter`, `AsyncContextConverter`) 는 common 에 두지 않는다.

#### Rationale

ABI 호환성이 유지되지 않는 컨버터를 common 에 두면 미래 jakarta 7 등에서 `AbstractMethodError` 위험. 보수적으로 enum/listener 변환만 둔다 ([50.architecture.md §2.2](../research/50.architecture.md)).

#### Acceptance Criteria

- [ ] `common/src/main/java/adapter/common/` 에 위 5개 클래스만 존재한다.
- [ ] common 의 어느 클래스도 `jakarta.servlet.HttpServletRequest`, `jakarta.servlet.http.HttpSession`, `jakarta.servlet.ServletContext`, `jakarta.servlet.AsyncContext` 등 5.0 → 6.0 에서 변경된 인터페이스를 직접 참조하지 않는다.
- [ ] `servlet5`, `servlet6`, `servlet61` 모듈이 모두 common 을 의존하며, 각자의 jakarta 버전 런타임에서 common 의 컨버터가 `AbstractMethodError` 없이 동작한다 (통합 테스트로 검증).

### FR-MOD-006 — 공통 진입점 + 버전별 별칭

| Field | Value |
|---|---|
| Type | functional |
| Target | v1.0.0 |
| Status | planned |
| Stability | evolving |
| Priority | high |
| Tags | entry-point, api |
| Related Docs | [50.architecture.md §4.3](../research/50.architecture.md) |
| Source | [80.decisions.md D2](../research/80.decisions.md) |

#### Requirement

각 버전 모듈은 다음 두 진입점 클래스를 제공한다.

| 클래스 | 위치 (5.0 예시) | 비고 |
|---|---|---|
| `com.snoworca.ServletAdapter` | `servlet5/src/main/java/com/snoworca/ServletAdapter.java` | 사용자 코드에서 단순 import. 모든 모듈이 동일 FQCN 사용 — 단일 ClassLoader 에서 한 모듈만 의존 시 충돌 없음 |
| `com.snoworca.ServletAdapter5` | 동일 디렉토리 | 별칭. ServletAdapter 와 동일 정적 메서드. 다른 jakarta 버전 모듈과 공존 시 (다중 ClassLoader 또는 reflection 호출) 사용 |

`servlet6` 모듈은 `ServletAdapter6`, `servlet61` 모듈은 `ServletAdapter61` 별칭을 제공한다.

진입점의 메서드 시그니처는 다음을 포함한다 (기존 `0.0.1` ServletAdapter 와 호환).

```java
public static jakarta.servlet.http.HttpServletResponse adaptToJakarta(javax.servlet.http.HttpServletResponse r);
public static jakarta.servlet.http.HttpServletRequest  adaptToJakarta(javax.servlet.http.HttpServletRequest r);
public static jakarta.servlet.ServletContext           adaptToJakarta(javax.servlet.ServletContext c);
public static jakarta.servlet.ServletRequest           adaptToJakarta(javax.servlet.ServletRequest r);
public static jakarta.servlet.ServletResponse          adaptToJakarta(javax.servlet.ServletResponse r);

public static javax.servlet.http.HttpServletResponse   adaptToJavax(jakarta.servlet.http.HttpServletResponse r);
public static javax.servlet.http.HttpServletResponse   adaptToJavax(javax.servlet.http.HttpServletResponse r);    // identity passthrough
public static javax.servlet.http.HttpServletRequest    adaptToJavax(jakarta.servlet.http.HttpServletRequest r);
public static javax.servlet.http.HttpServletRequest    adaptToJavax(javax.servlet.http.HttpServletRequest r);     // identity passthrough
public static javax.servlet.ServletContext             adaptToJavax(jakarta.servlet.ServletContext c);
public static javax.servlet.ServletContext             adaptToJavax(javax.servlet.ServletContext c);              // identity passthrough
public static javax.servlet.ServletRequest             adaptToJavax(jakarta.servlet.ServletRequest r);
public static javax.servlet.ServletRequest             adaptToJavax(javax.servlet.ServletRequest r);              // identity passthrough
public static javax.servlet.ServletResponse            adaptToJavax(jakarta.servlet.ServletResponse r);
public static javax.servlet.ServletResponse            adaptToJavax(javax.servlet.ServletResponse r);             // identity passthrough
```

`adaptToJakarta(jakarta X)` homogeneous 오버로드도 대칭적으로 추가한다 — 항등 반환.

#### Rationale
