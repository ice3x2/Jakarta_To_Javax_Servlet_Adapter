### FR-FIX-001 — StreamConverter.read 가 readLine 호출하는 결함 수정

| Field | Value |
|---|---|
| Type | functional |
| Target | v1.0.0 |
| Status | planned |
| Stability | evolving |
| Priority | critical |
| Tags | bug, stream, data-corruption |
| Related Docs | [60.conversion-strategy.md §6.12 D1](../research/60.conversion-strategy.md) |
| Source | [80.decisions.md D1.1](../research/80.decisions.md) |

#### Requirement

`adapter.servletElementConverter.StreamConverter#convert(jakarta.servlet.ServletInputStream)` 및 대칭 javax 변환 메서드 내부의 익명 InputStream 구현에서, `read(byte[] b, int off, int len)` 가 원본의 `readLine(b, off, len)` 을 호출하는 오류를 수정한다.

수정 후 동작: `read(byte[], int, int)` 는 원본의 동명 메서드 `read(byte[], int, int)` 로 위임한다. `readLine` 은 별도 메서드 시그니처로 유지한다.

#### Rationale

`ServletInputStream.readLine` 은 LF 또는 buffer 끝까지만 읽는 line 모드. 일반 binary 데이터 읽기 시 line terminator 에서 잘못 멈춰 데이터 손상 발생.

본 결함은 어댑터의 `getInputStream()` 을 통과한 모든 본문 읽기에 영향. 멀티파트 업로드, JSON / Protobuf / 바이너리 응답 등에서 무성한 silent corruption.

#### Acceptance Criteria

- [ ] `StreamConverter.java:41` (jakarta 방향) 의 `read(byte[], int, int)` 가 `inputstream.read(b, off, len)` 을 호출한다.
- [ ] `StreamConverter.java:93` (javax 방향) 의 동일 메서드도 동일하게 수정된다.
- [ ] `readLine(byte[], int, int)` 시그니처는 별도로 유지되며 원본의 `readLine` 으로 위임된다.
- [ ] BM01 회귀 테스트가 통과한다 (수정 전 코드에서는 실패).

### FR-FIX-007 — jakarta ServletRequest.getRealPath 메서드 처리

| Field | Value |
|---|---|
| Type | functional |
| Target | v1.0.0 |
| Status | planned |
| Stability | evolving |
| Priority | high |
| Tags | bug, removed-method |
| Related Docs | [60.conversion-strategy.md §6.12 D7](../research/60.conversion-strategy.md) |
| Source | [80.decisions.md D1.7](../research/80.decisions.md) |

#### Requirement

`adapter.jakarta.servlet.ServletRequest#getRealPath(String path)` 는 jakarta 5.0+ `ServletRequest` 인터페이스에 부재하는 메서드다. 본 결함을 다음과 같이 처리한다.

- jakarta 5.0+ `ServletRequest` 의 javadoc 을 확인한다.
- 부재 시 `@Override` 어노테이션과 메서드 자체를 어댑터에서 **제거**한다 (인터페이스에 없으므로 사용자가 호출할 경로 없음).
- 단 사용자가 어댑터 구체 타입을 통해 호출하는 경우를 대비해 deprecated alias 로 유지하고 싶다면, `@SuppressWarnings("deprecation")` + javax 측 deprecated alias 로 위임하되 jakarta override 표기는 제거한다.

`adapter.javax.servlet.ServletRequest` 측은 javax 4.0 에 deprecated 으로 존재하므로 위임을 그대로 유지한다.

#### Rationale

### FR-FIX-008 — ServletReqResConverter 의 잘못된 instanceof 분기 검토

| Field | Value |
|---|---|
| Type | functional |

#### Requirement

`adapter.servletElementConverter.ServletReqResConverter#convert(jakarta.servlet.ServletResponse)` 의 분기 `instanceof javax.servlet.http.HttpServletResponse` 가 항상 false 인 결함을 검토 및 수정한다.

수정 후 동작:
- 분기 검사 대상이 `instanceof jakarta.servlet.http.HttpServletResponse` 여야 한다 (양방향 모두 동일 namespace).
- HTTP 응답이 일반 ServletResponse 래퍼로 다운그레이드되지 않고 적절한 `HttpServletResponse` 어댑터로 wrap 된다.

대칭으로 `convert(jakarta.servlet.ServletRequest)`, `convert(javax.servlet.ServletResponse/Request)` 의 모든 instanceof 분기를 검토한다.

#### Rationale

instanceof 검사 namespace 가 틀어지면 분기가 항상 false → HTTP 응답이 다운캐스트되지 않아 `HttpServletResponse` 전용 메서드 (예: `addCookie`, `sendRedirect`) 호출 시 `ClassCastException` 또는 메서드 누락. 70.md 의 F4 결함 — 통합 테스트로만 잡힌다고 식별됨.

#### Acceptance Criteria

- [ ] `ServletReqResConverter.convert(...)` 가 jakarta `HttpServletResponse` 인스턴스를 받으면 어댑터의 `adapter.javax.servletN.http.HttpServletResponse` 를 반환한다 (`instanceof` 로 확인).
- [ ] 4개 방향 (javax→jakarta, jakarta→javax × Request/Response) 모두 동일하게 동작한다.
- [ ] BM04 회귀 테스트 통과.
- [ ] 통합 테스트 IT01 (HttpServletResponse 메서드 호출) 통과.
