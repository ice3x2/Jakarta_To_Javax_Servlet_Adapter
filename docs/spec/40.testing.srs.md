## 1. Scope Overview

본 문서는 1.0 의 테스트 인프라 요구사항을 정의한다. 5단계 테스트 피라미드 (단위 / contract / 통합 / 크로스버전 / 회귀), Tomcat embed 통합, JaCoCo 커버리지 게이트, CI 매트릭스, PIT mutation testing 도입 시점을 포함한다.

상세 전략은 [docs/research/70.testing-strategy.md](../research/70.testing-strategy.md) 참조.

## 2. Scope Boundaries

### In Scope

- 단위 / contract / 통합 / 크로스버전 / 회귀 테스트 인프라
- Tomcat embed (10.0.x / 10.1.x / 11.x) 통합
- Mockito 5.x 기반 mock 전략
- JaCoCo 커버리지 측정 + 게이트
- GitHub Actions CI 매트릭스
- 회귀 테스트 슈트 (Bug Museum)
- PIT mutation testing — v1.1.0 도입 예정 (Phase 5)

### Out of Scope

- 결함 자체의 수정 코드 (→ `FIX`)
- 변환 의미론 사양 (→ `CONV`)
- 모듈 토폴로지 (→ `MOD`)

## 3. Assumptions and Constraints

- Mockito 5.6.0 + JUnit 5.9.2+ 사용 (현 build.gradle 와 호환).
- Tomcat embed 의존성은 `testImplementation` scope 로만 추가 (사용자 의존 누출 없음).
- CI 환경에 JDK 17 만 설치되어 있고 Gradle Toolchain 으로 JDK 8 / 11 자동 다운로드 가능.
- 통합 테스트는 Linux only (Windows 는 단위 + contract 만).

#### Requirement

각 어댑터 클래스의 모든 위임 메서드를 Mockito 기반으로 단위 테스트한다. 각 메서드별 다음을 검증.

### FR-TEST-002 — Reflection 기반 Contract 테스트 (L2)

| Field | Value |
|---|---|
| Type | functional |
| Target | v1.0.0 |
| Status | implemented |
| Stability | stable |
| Priority | critical |
| Tags | contract-test, reflection |
| Related Docs | [70.testing-strategy.md §5](../research/70.testing-strategy.md) |

#### Requirement

`DelegationContractTest` 클래스를 작성하여, jakarta / javax 인터페이스의 모든 public 추상 메서드를 reflection 으로 enumerate 한 뒤 어댑터에 호출하고 원본 mock 의 동명 메서드가 호출되었는지 `verify` 한다.

핵심 알고리즘 ([70.testing-strategy.md §5.2](../research/70.testing-strategy.md)):

1. 어댑터 spec 등록 (대상 인터페이스 + 원본 인터페이스 + factory).
2. 인터페이스 메서드 enumerate.
3. blacklist (Object 메서드, 변환 정책 메서드) 제외.
4. sample args 로 어댑터 호출.
5. 원본 mock 의 동일 시그니처 메서드가 호출되었는지 verify.
6. `verifyNoMoreInteractions(origin)` 로 잘못된 메서드 호출 검출.

본 테스트 driver 는 `common/src/testFixtures` 에 두어 5/6/6.1 모듈 모두 공유.

#### Rationale

위임 누락은 가장 빈번한 결함. 인터페이스에 새 메서드가 추가될 때 어댑터가 빠뜨리면 자동 검출. 6.0/6.1 신규 메서드 (`getRequestId` 등) 의 누락 검증에 결정적.

#### Acceptance Criteria

- [ ] `DelegationContractTest` 가 `common/src/testFixtures/java/com/snoworca/contract/` 에 작성된다.
- [ ] 각 버전 모듈의 test 가 본 driver 를 호출하여 어댑터 spec 을 등록한다.
- [ ] 모든 어댑터 인터페이스 (`HttpServletRequest`, `HttpServletResponse`, `HttpSession`, `ServletContext`, `ServletRequest`, `ServletResponse`, `Cookie`, `Part`, `AsyncContext` 등) 의 모든 추상 메서드에 대해 위임 검증이 자동 수행된다.
- [ ] 의도적 변환 정책 메서드 (예: `setStatus(int, String)` 폴백) 는 blacklist 또는 별도 단위 테스트로 보완된다.

동일 시나리오 (예: simple GET + body) 를 5.0 / 6.0 / 6.1 세 모듈의 통합 테스트에서 모두 실행하여 **외부 관찰 가능한 결과 (HTTP 응답) 가 동등** 함을 검증한다.

실현 방식: 각 모듈에 동일 시나리오 사본 (또는 common 의 test-fixtures 를 통한 shared scenario). CI 매트릭스로 모든 모듈을 병렬 실행하여 결과 비교.

본 SRS 는 cross-version classpath 공유 (한 JVM 에 Tomcat 10.0/10.1/11 동시 임베드) 를 시도하지 않는다 — 별도 빌드 매트릭스 (CI 셀) 로 격리.

#### Acceptance Criteria

- [ ] 시나리오 IT01 (단순 GET) 가 세 모듈에서 다음 항목이 모두 동일하다:
  - HTTP status code (예: 200).
  - Response body 가 byte-for-byte 동일 (charset 변환 후 String 비교).
  - `Content-Type` 헤더의 MIME type + charset 동일.
- [ ] 시나리오 IT03 (Cookie) 가 세 모듈에서 다음 항목이 모두 동일하다:
  - Set-Cookie 헤더의 `name=value` 부분 동일.
  - Set-Cookie 의 attribute (Path, Domain, Max-Age, HttpOnly, Secure) 중 IT 시나리오가 명시 설정한 값 동일. `Expires` 같은 비결정적 timestamp 는 제외.
- [ ] 시나리오 IT05 (Session) 가 세 모듈에서 다음 항목이 모두 동일하다:
  - `JSESSIONID` Cookie 생성 여부.
  - 두 번째 요청에서 동일 session 의 attribute 값 조회 성공.
- [ ] CI 매트릭스에서 세 모듈이 병렬 실행되며 결과가 한 보고서에 통합된다.

### OPS-TEST-002 — PIT mutation testing (v1.1.0 도입)

| Field | Value |
|---|---|
| Type | operational |
| Target | v1.1.0 |
| Status | planned |
| Priority | medium |
| Stability | draft |
| Tags | mutation-testing, pit, nightly |
| Related Docs | [70.testing-strategy.md §14.3, §19](../research/70.testing-strategy.md), [80.decisions.md D6](../research/80.decisions.md) |

#### Requirement

PIT mutation testing (`info.solidsoft.pitest` Gradle plugin) 을 v1.1.0 출시 시점에 도입한다. 실행 정책:

- 매 PR: 실행 안 함 (빌드 시간 +30~60초 부담).
- nightly cron: 실행, mutation score ≥ 80% 게이트.
- release tag 푸시: 실행, 통과 의무.

설정 예시:
```groovy
pitest {
    targetClasses = ['adapter.**', 'com.snoworca.**']
    mutators = ['STRONGER']
    mutationThreshold = 80
    coverageThreshold = 90
}
```

v1.0.0 범위에는 도입하지 않는다 (사용자 결정 D6 = "권장 사항으로", Phase 5).

#### Rationale

위임 위주 코드의 가장 효과적 결함 검출 도구. JaCoCo 라인 커버리지 만으로는 "메서드 호출 자체 누락" 을 잡지 못함. PIT 의 `VOID_METHOD_CALLS` 뮤테이터가 잡는다.

#### Acceptance Criteria

- [ ] v1.1.0 시점에 `build.gradle` 에 PIT 플러그인 적용.
- [ ] nightly + release tag 트리거의 CI job 이 추가된다.
- [ ] mutation score ≥ 80% 를 만족한다.
