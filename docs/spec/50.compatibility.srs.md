## 1. Scope Overview

본 문서는 1.0 출시의 호환성·게시·마이그레이션 관련 요구사항을 정의한다. artifactId 명명, 모듈 version 정책, 0.x → 1.0 마이그레이션 경로, 호환성 매트릭스 문서화, Maven Central 게시 준비를 다룬다.

## 2. Scope Boundaries

### In Scope

- artifactId 명명 규칙 (5개 모듈)
- 모듈 version 동기 정책
- 0.x → 1.0 사용자 마이그레이션 가이드 (alias 패키지)
- README + 호환성 매트릭스 문서
- Maven Central 게시 자격 준비

### Out of Scope

- 모듈 토폴로지 자체 (→ `MOD`)
- 변환 의미론 (→ `CONV`)
- 테스트 인프라 (→ `TEST`)
- 옵션 A (별도 `0.x` alias artifact 게시) — 80.decisions.md §1 D8 옵션 B 채택으로 본 v1.0 에서 out of scope. OQ-001 closed (2026-05-19).

## 3. Assumptions and Constraints

- group: `com.clipsoft` 유지 (build.gradle 의 현 값).
- Maven Central 게시는 Sonatype 계정 + GPG 키가 별도 준비되어 있다 (외부 의존).
- README 의 사용자 가이드는 한국어와 영어 양쪽으로 작성될 수 있다 (현 README 는 영문).

### MIG-REL-001 — 0.x → 1.0 마이그레이션 경로

| Field | Value |
|---|---|
| Type | migration |
| Target | v1.0.0 |
| Status | planned |
| Stability | evolving |
| Priority | high |
| Tags | migration, backward-compat, alias, deprecated-alias |
| Related Docs | [50.architecture.md §7](../research/50.architecture.md), [80.decisions.md §2 D8](../research/80.decisions.md) |

#### Requirement

0.0.1 사용자가 1.0 으로 옮길 때 호환성 보장 정책은 **옵션 B (servlet5 모듈 내 deprecated alias 패키지)** 를 채택한다 — 80.decisions.md D8 확정.

**채택 정책:**

- 1.0 의 `servlet5` 모듈에 `adapter.jakarta.servlet.*`, `adapter.javax.servlet.*`, `adapter.servletElementConverter.*` (0.x 패키지명) 을 `@Deprecated(since = "1.0.0", forRemoval = true)` alias 로 유지.
- 각 alias 클래스는 `adapter.jakarta.servlet5.*` 등의 실제 1.0 구현 클래스를 **상속 또는 위임**.
- alias 는 servlet5 모듈에만 포함 — servlet6 / servlet61 모듈은 0.x 패키지명 alias 없음 (신규 사용자 전용).
- 1년 후 v2.0 (목표: 2027 Q1) 에서 alias 제거.
- 별도 0.x artifact 백포팅 라인은 운영하지 않음 (단일 게시 트랙).

#### Rationale

옵션 A (별도 0.x artifact) 대비 옵션 B 채택 근거:

- **운영 단순화**: 단일 Maven Central 게시 트랙. 0.x 백포팅 부담 0.
- **결함 fix 즉시 전파**: alias 가 servlet5 의 실제 구현을 위임하므로 D1 9건 fix 가 alias 사용자에게도 자동 적용. cherry-pick 백포팅 부담 0.
- **IDE 워닝 직접 전달**: `@Deprecated` 어노테이션 → 사용자 코드에 컴파일러 워닝 표시 → 자연스러운 마이그레이션 유도.
- **버전 분기 위험 0**: 단일 codebase. 0.x 와 1.x 의 diverge 가능성 없음.
- **0.0.1 사용자 베이스 작음**: alias 부담 자체가 작음. jar size 증가는 minor (대부분 1~3줄 wrapper 클래스).

비용: servlet5 jar size 증가 (alias 클래스 수십 개), alias 경로 회귀 테스트 minimal 부담.

#### Acceptance Criteria

- [ ] `jakarta-to-javax-servlet-adapter-servlet5:1.0.0` 의 jar 안에 `adapter.jakarta.servlet.*`, `adapter.javax.servlet.*`, `adapter.servletElementConverter.*` (0.x 패키지명) 의 alias 클래스가 포함된다.
- [ ] 모든 alias 클래스에 `@Deprecated(since = "1.0.0", forRemoval = true)` 어노테이션이 부착된다.
- [ ] 각 alias 클래스는 `adapter.jakarta.servlet5.*` 등의 실제 1.0 구현 클래스를 상속 또는 위임한다 (자체 구현 로직 보유 금지).
- [ ] 0.0.1 사용자가 자기 코드의 `import adapter.jakarta.servlet.http.HttpServletRequest` 를 변경하지 않고 의존만 `jakarta-to-javax-servlet-adapter-servlet5:1.0.0` 으로 업그레이드했을 때 컴파일이 성공하며 `@Deprecated` 컴파일러 워닝이 표시된다.
- [ ] alias 경로의 BM01~BM10 회귀 1~2건 샘플 테스트가 servlet5 모듈에 포함된다 (cosmetic 검증).
- [ ] README + CHANGELOG 에 마이그레이션 가이드 + v2.0 (목표: 2027 Q1) alias 제거 일정이 명시된다.
- [ ] 각 alias 클래스의 Javadoc 에 "Use `adapter.jakarta.servlet5.*` instead" 가이드가 명시된다.
- [ ] servlet5 jar size diff (alias 포함/미포함) 가 CHANGELOG 에 기록된다.

#### Implementation Notes

- OQ-001 종결 (80.decisions.md D8) 후 본 REQ 의 verification 진행 가능.
- alias 클래스 생성은 **위임 패턴** 권장 (필드 + 생성자 위임), 상속은 final 클래스 회피 위해 신중. 단순 wrapper 가 일반적으로 단순함.
- alias 의 정적 메서드/필드는 동일 시그니처로 재정의 필요.
- v2.0 alias 제거 시 마이그레이션 가이드를 README 에 별도 섹션으로 작성.
